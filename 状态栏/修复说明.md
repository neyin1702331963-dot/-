# 状态栏修复说明

针对三个问题：AI 正文生成的状态栏 NPC 列表为空、USER 立绘下一轮不继承、立绘抓取正则。

## 一、为什么"示例成功、AI 正文失败"

旧版脚本挂在 `<img src="x" onerror>` 上，并且 **只跑一次**：

```js
onerror="...setTimeout(function(){ var shell=img.closest('.gal-status-shell'),
                                   raw=shell&&shell.querySelector('.gal-status-raw');
                                   if(!shell||!raw)return; ... },80)"
```

- **状态栏示例**是整段一次性插进 DOM 的，`<img>` 触发 `onerror` 时 `.gal-status-raw` 已经写满了 → 解析成功。
- **AI 正文是流式逐字输出**的。`<img>` 标签排在 `<div class="gal-status-raw">` **前面**，所以它先被解析、`onerror` 立刻触发；80ms 后 `raw` 里往往只到 `<div protocol>`、`<div top>`，**`<div npc>` 还没送到**。脚本读到空的 npc → `npcs.length === 0` → 显示 `0 / 0`、"暂无人物"。而前端后续是**增量 patch**（只补文本、不重建 `<img>`），`onerror` 再也不会触发，于是永远停在那一刻的半成品状态。

这解释了截图 2 的每一个细节：顶栏时间/事件有值（前几个区块 80ms 内到了），NPC 却是 `0 / 0`。

已用 Playwright + Chromium 复现：把旧版文件放进同一套测试里跑，`[3] 流式增量 patch` 组**必挂**，顶栏 PASS 而 NPC 进度是 `0 / 0`——和你的截图一模一样。

### 附带的第二个 bug
`npcs` 为空时旧脚本执行 `body.hidden=true`，但 CSS 里 `.gal-status-npc-body{display:grid}` 的优先级压过了 `[hidden]` 的浏览器默认样式，所以面板**根本没被隐藏**，照样显示一整屏"暂无"——也就是截图 2 里那堆空字段。

## 二、改了什么

### 1. `02-状态栏HTML+JS-常驻.txt`：一次性脚本 → 常驻引擎

- `window.__galStatusEngine` **全局只装一次**，之后任何一条状态栏的 `<img>` 再触发也只是叫醒它，不会重复安装。
- 用 **MutationObserver（150ms 防抖）+ 2s 轮询兜底** 驱动渲染：不管内容是流式追加、整段重解析、还是懒加载历史消息，都会被重新渲染。
- 每个状态栏用 **内容签名去重**（`shell.galSig`）：内容没变就不重画，避免流式期间反复重排。
- **一次扫描全部状态栏**（`document.querySelectorAll('.gal-status-shell')`），不再依赖 `img.closest()`——`img` 被前端 patch 掉/脱离文档时旧版直接静默 `return`。
- 重渲染时**保留当前选中的 NPC**（按名字记忆，`shell.galActive`），流式刷新不会把你切到的人物弹回第一个。
- 全程 `try/catch` 兜底，单条状态栏出错不影响其它。

### 2. USER 立绘持久化

- 上传后写入 `localStorage` 的 `CUSTOM_galStatusUser_v1`（平台要求走白名单前缀，见下节 B），**同时保存在内存**（localStorage 被禁用时自动降级，隐私模式也不会报错）。
- 每次渲染都会把立绘**回填到页面上所有状态栏**，所以下一轮、下下轮、以及刷新页面后都在。
- 上传前用 canvas **压到最长边 768px**（webp 0.85，不支持 webp 退 jpeg），避免几 MB 的原图撑爆 localStorage 配额。
- 新增右上角 **× 清除按钮**（`has-image` 时才出现），同时清掉 localStorage。

### 3. NPC 立绘

- 新增 `data-gal-portrait-base="https://meimoaiimg.com/user/1462820/"`（写在 `.gal-status-shell` 上）。
- **正则没生效时 JS 会自己拼链接**：读到 `立绘=橘诗夜_学园校服` 这种原始值，就用 base + `encodeURIComponent(名)-encodeURIComponent(形态).png` 兜底。正则和脚本任意一个能用，立绘就能出来。
- 换图床只需要改两处同一个前缀：02A 的替换内容 + 02 的 `data-gal-portrait-base`。

### 4. 解析容错

- 分隔符除 `;;` 外**也按换行切分**：AI 漏写行尾 `;;` 时整块不再报废。
- 自动把全角 `；； ：： ｜ ＝` 归一成半角，AI 打错标点不再整块读不出来。
- 区块查找从 `div[npc]` 放宽到 `[npc]`，前端把标签换成别的元素也能找到。
- `立绘` 尾部空格会被剥掉（旧正则会生成 `.../学园校服 .png` 这种必然 404 的链接）。

### 5. `01-状态栏CSS-常驻.txt`

- 新增 `.gal-status-npc-body[hidden]{display:none!important}`（含两个媒体查询内），修掉上面说的 `[hidden]` 失效。
- 新增 `.gal-status-user-clear` 清除按钮样式。
- 补上脚本里一直在用、CSS 里却没定义的 `.is-selected` 点击反馈样式。
- 其余样式一行未动。

### 6. `02A-NPC立绘抓取正则.txt`

```
旧: 立绘=([^_\s|;]+)_([^|;\r\n]+)
新: /立绘=[ \t]*(?!https?:)([^_|;\s]+)_([^|;\r\n]+?)[ \t]*(?=[|;\r\n]|$)/
```

- **补上首尾的 `/ /`**——这条最要命，见下一节。
- `(?!https?:)`：已经是链接的不再二次转换（规则顺序变化或重复执行时不会把链接当成"名_形态"再转一遍）。
- 惰性 + 尾部空白剥离：修掉 `立绘=名_形态 |` 生成带空格的坏 URL。
- 等号后允许空格。

## 二之二、按官方《聊天页正则 JS 写法指南》复核后的三处修正

拿到平台文档后逐条核对，发现三处会静默失效的地方，已改：

### A. 立绘正则少了首尾斜杠 → 一直被当纯文字字面匹配

文档第 4 节：「`/规则/` 正则匹配」「纯文字 完全按字面匹配」。原来那条 `立绘=([^_\s|;]+)_(...)`
没有斜杠，平台会拿这串**字面量**去逐字找，永远匹配不到。

这解释了一个之前没注意到的现象：**两张截图里 NPC 立绘框都写着"暂无立绘"**——包括那张"成功"的
示例图。立绘从来就没转换成过链接。已加上 `/ /`。

（`<status>`、`</status>`、`《状1》` 这三个触发词反而**就该是纯文字**，不要加斜杠。）

### B. localStorage 的 key 必须走 `CUSTOM_` 白名单前缀

文档第 9 节：「只有白名单内的 key 才能读写；不在名单里的 key，`setItem` 会被**静默忽略**，
`getItem` 返回 `null`」。我原来用的 `galStatusUserPortrait` 不在名单里，USER 立绘**刷新后
必然丢失**（同一页内靠内存变量还在，所以下一轮看着是好的，一刷新就没了——很隐蔽）。

已改为文档推荐的自定义前缀：`CUSTOM_galStatusUser_v1`。

### C. `<section>` / `<header>` 在 AI 回复里会被平台删掉

文档第 2 节：「AI 回复里会被删掉：`section header footer nav iframe canvas audio form` 等」。
原版骨架用了 3 个 `<section>` + 4 个 `<header>`，正好全在 AI 回复这条路径上。

已全部换成 `<div>` 并保留原有 class。CSS 里没有任何元素选择器依赖这两个标签，**渲染效果零变化**
（`修复后-*.png` 是换完之后重新截的）。

### 另外顺带对齐的两点

- 全局名改成文档建议的 `window.__` 唯一名（`window.__galStatusEngine` / `window.__galStatusInject`），
  避免和同一张卡里别的正则撞名；同时保留 `window.galStatusInject` 别名，不影响你已有的其它规则。
- 已确认替换内容里**不含 `$` 和 `{{`**，不会被平台的 `$1` / `$字段名` / `{{random:...}}` 语法误伤
  （测试里加了断言长期守住这一点）。

### 复核过、不用改的部分

- 「只改变玩家看到的界面，不会改掉发给 AI 的原文」——所以这一大段 HTML **不吃上下文 token**。
- `onclick` / `onerror` 等内联事件在替换内容里是官方支持的写法，现在这套注入方式没问题。
- 文档也支持在替换内容里写 `<script>`，但它「同一段脚本只加载一次」；而 `<img onerror>` 是
  **每条状态栏各触发一次**，更适合用来叫醒引擎，所以保持现状。
- 「后添加的规则可能先执行」——正因为顺序不保证，02A 才做成幂等的，且 02 里有拼链接兜底。
