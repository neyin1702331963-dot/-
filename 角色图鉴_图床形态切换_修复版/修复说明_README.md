# 角色图鉴「图床形态切换」修复说明

## 问题现象
一个角色默认 5 张立绘，点击图片右下角的 `1/5` 按钮应当切换到下一张形态，
但是在平台（美墨 / meimoaiimg 图床那套）里点击没有任何反应。
而图鉴目录、Archive 分页（魔法少女 / 魔女 / 特殊角色）等都正常。

## 根本原因
切换功能原本依赖骨架模板里的一段 `<script>`，它在页面加载时定义了全局函数
`window.cgSwitchFormBtn`，按钮再通过

```html
onclick="return window.cgSwitchFormBtn?window.cgSwitchFormBtn(this):false"
```

去调用它。

**平台出于安全（防 XSS）会把用户 HTML 里的 `<script>` 标签整段过滤掉，**
但保留 `onclick` 这类内联事件。结果是：

- `<script>` 被删 → `window.cgSwitchFormBtn` 从未被定义；
- 按钮的 `onclick` 里那个三元判断发现函数不存在，直接 `return false`，什么都不做；
- 脚本里那个 `document.addEventListener('click', …)` 的兜底监听同样没机会注册。

而图鉴目录 / 分页切换用的是**完全自包含的内联 onclick**（不依赖任何外部函数），
所以它们不受影响、照常工作。这正好解释了「为什么别的都行、只有图片切换没效果」。

## 修复方式
把切换逻辑从 `<script>` 里搬出来，**整段写进按钮自己的 `onclick`**，
做到和分页按钮一样完全自包含、不依赖任何 `<script>`：

- `01_骨架模板…txt`：删除了原来那段 `<script> … </script>`（已不再需要，留着反而会和内联逻辑重复触发，导致一次点击跳两张）。
- `03_魔法少女图鉴…txt`：7 个会切换形态的角色（五堂爱 / 南琴里 / 卡娜·瓦卢瓦 / 叶凝云 / 尹璃银 / 橘诗夜 / 芒舒窈），按钮的 `onclick` 全部替换为自包含版本。

自包含 onclick 做的事情和原函数完全一致：读取角色卡上的 `data-forms`（JSON 5 个形态）→
下标 +1 取模循环 → 更新立绘 `img.src/alt`、`data-form-index`、角色定位
`.custom-char-role`、台词 `.custom-char-quote`、事件记录 `.custom-char-event`
（带「形态记录」加粗前缀）、标签 `.custom-char-tags`，以及按钮上的 `当前/总数`，
并加了 100ms 防抖避免连点跳两张。

CSS（`02`）、魔女图鉴（`04`）、特殊角色（`05`）无需改动，未改动。

## 使用方法
平台上各字段还是按原来的拆分包贴：
1. 骨架模板贴 `01`（注意里面的 `[图鉴ID]`、`[魔法少女图鉴]` 等占位符照旧替换）；
2. CSS 贴 `02`；
3. 三个图鉴内容分别贴 `03 / 04 / 05`。

贴好后即使平台过滤掉 `<script>`，点击立绘也能正常在 5 张形态间循环切换。

## 验证
已用 Node + 模拟 DOM 对自包含 onclick 跑过点击：下标 1→0→1→0 正确循环，
立绘 src/alt、角色定位、台词、事件（含加粗前缀）、标签、按钮计数均逐次正确更新，
标签/事件不会累积重复，符合预期。
