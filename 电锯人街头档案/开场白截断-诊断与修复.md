# 电锯人·街头档案 — 开场白「显示到角色立绘选择就断了」诊断与修复

> 现象：MMD 导入后，开场白「面包」渲染到 **角色立绘选择** 标题就中断，
> 下面的立绘轮播 / 外貌 / 种族 / 天赋 / 开局事件 / 建档按钮 + 末尾 `img onerror` 引擎全部不显示。
> 期望：完整渲染（立绘轮播 + 后续全部区块）。

## 根因：markdown（vditor）管线把「空行 + 缩进」误判为代码块/段落，截断后续 HTML

排查结论（逐项实测/比对）：

1. **不是标签净化**：全文标签只用白名单（`div span img input button style`），且开闭完全平衡
   （div 342/342、span 48/48、button 5/5、style 2/2）。排除「非白名单/未闭合被剥离」。
2. **不是长度上限**：截断点正好落在一个 markdown 结构边界上，不是某个整数字符数。
3. **真因 = 注入 HTML 里有「空行」+「≥4 空格缩进」**：

   MMD 气泡走 markdown 管线（vditor）。原文里多处是
   ```
   （空行）
   ····<div class="...">      ← 4 个空格缩进
   ```
   markdown 规则：**空行结束当前 HTML 块；其后缩进 ≥4 空格的行被当成「缩进代码块」**，
   于是从该处起的 HTML 不再当标签渲染，后续结构错位 → 整段「断掉」。

   决定性证据：可见的建档面板里，**第一处「空行 + 4 空格缩进 `<div>`」就出现在
   `角色立绘选择` 的输入框之后**（原文 1311 空行 → 1312 `    <div class="ava-selector-container">`）。
   截断点与它**精确重合**。在它之前的空行后面跟的都是 0~2 空格缩进的 `<div>`（不触发代码块），所以前面正常。

   这正是 skill `references/platforms/mmd-old.md` 记录的
   「**注入 HTML 的换行/空行被 vditor 补成空 `<p>`/打断布局**」陷阱，
   官方修法是「**注入 HTML 写成单行无缝（标签间零换行、无缩进）**」。

## 修复：把开场白 HTML 压平成单行（零换行、零缩进、去空行）

- 产物：`output/开场白-单行修复版.txt` —— 把整段开场白去掉所有换行/空行/行首缩进，
  以单空格安全拼接为**一行**。空格分隔比无缝拼接更稳（避免 CSS `0 6px`→`18px` 这类跨行属性值被并字），
  且空格不会被 markdown 解析成段落，不产生空 `<p>`。
- 校验：输出 0 换行；所有标签开闭仍平衡；
  立绘轮播 / 外貌 / 种族 / 天赋 / 事件转盘 / 建档引擎（`img onerror`）等区块全部保留。
- 结构红线仍满足：最外层容器带 `onclick="event.stopPropagation()"`；末尾 `img onerror` 引擎在容器闭合 `</div>` 之前。

## 关键约束：开场白上限 4000 字符（skill 未记载，实测）

MMD **开场白（`beginning`/`first_mes`）有 4000 字符上限**（skill 文档没写）。本卡 HTML 单行约
15.4 万字符，**根本塞不进开场白**——所以不能把整段 HTML 放 `beginning`。
（注意：这条 4000 是开场白上限；正则 `replaceString` 是另一条 20000 上限，两者不同。）

## 踩坑修正：链式注入会整页空白（已弃用）

第一版用「链式」：`beginning` 放 `<标记1>`，正则1 把它换成 `第1段+<标记2>`，正则2 再换 `<标记2>`……
**实测整页空白**。原因：链式依赖「MMD 重扫上一条替换出的内容」，但实测**不重扫**——只有 `<标记1>`
被换，后面标记全是死标记；而**第 1 段前 19500 字符整段落在顶部那个 7 万字符的 `<style>` 里**，
替换出来就是个**没闭合的 `<style>`**，浏览器把后面全当 CSS 吞掉 → 全白。

## 正确交付 = 全标记预置（不链式）

把 **8 个标记全部预先塞进 `beginning`**，每条正则各自替换自己的标记——**不依赖重扫**，任何一条都独立命中：

- `beginning = "<mbseg1><mbseg2>…<mbseg8>"`（64 字符，≪4000）
- 正则 n：`<mbsegN>` → `第 N 段 HTML`（各段无尾标记，互不依赖）
- 8 段按顺序替换后，拼回 == 原单行 HTML。

校验（已跑）：
- 「**MMD 不重扫**」最坏模型模拟：拼回 == 原 HTML、无残留标记、`<style>` 2 开 2 闭、div 342/342 平衡、尾部引擎在。
- 单条 replaceString ≤19500（≤20000）、`beginning` 64 字符（≤4000）。
- skill `build-preview.py --platform mmd` 生成的沙箱/全景预览里，各区块齐全、`<mbseg` 残留为 0。
- `json.tool` + `validate.py --platform mmd` 0 错误（少量 WARN 为「按段单看」误报/原卡既有写法，非本次引入）。

产物：
- `output/电锯人街头档案-MMD导入.json`：MMD「正则导入」直接吃（8 段全标记预置版）。
- `output/电锯人街头档案-MMD导入-preview-mmd.html` / `-panorama-mmd.html`：模拟正则管线后的渲染预览，浏览器打开自查。
- `output/开场白-单行修复版.txt`：完整单行 HTML（拆分用源、备查）。

> 标记为何用 `<mbsegN>`：与平台验证过的 `<css>`/`<ztl>` 同款角括号机制；原 HTML 不含 `<mbseg`，不冲突。
> 浏览器预览不复现 vditor 换行陷阱，「预览正常」≠「MMD 正常」，最终以实机为准。

## 给以后做卡的提醒（写法红线）

- **开场白/AI 回复里注入的 HTML 一律压成单行**：标签间不留换行、行首不留缩进、不留空行。
- 想要源码可读 → 维护一份带缩进的「源」，**交付前用压平脚本**生成单行版再导入。
- `onerror` / `onclick` 内的 JS 本来就必须单行无换行符（CSP 审查），顺带一起遵守。
